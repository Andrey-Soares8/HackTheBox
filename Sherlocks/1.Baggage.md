# HTB Sherlock Writeup: Baggage 🧳

**Nível:** Very Easy | **Categoria:** DFIR | **Temas:** Shellbags, Registry Forensics, Data Exfiltration

Este writeup documenta a investigação do Sherlock **Baggage** do Hack The Box, no qual analisamos uma coleta KAPE de uma estação Windows comprometida para reconstruir, apenas a partir dos artefatos de **Shellbags** (e alguns artefatos de registro de apoio), o que o usuário comprometido **steve** acessou: a ferramenta trazida para buscar dados sensíveis, as pastas de senhas e VPN, o compartilhamento de rede da produção e o arquivo montado para exfiltração.

---

## 🗂️ 1. Cenário e Evidências

A evidência é uma coleta do **KAPE** (target `RegistryHivesUser`) feita na máquina `PROD-WORKSTATIO` (Windows 10, build 22621). O `ConsoleLog` do KAPE registra a linha de comando usada:

```text
--tsource C: --tdest C:\Windows\Temp\artifacts --tflush --target RegistryHivesUser --gui
```

Estrutura da coleta:

```text
C/Users/steve/NTUSER.DAT (+ ntuser.dat.LOG1/LOG2)
C/Users/steve/AppData/Local/Microsoft/Windows/UsrClass.dat (+ UsrClass.dat.LOG1/LOG2)
C/Users/admin/...            (mesmos hives do usuário admin)
C/Users/Default/NTUSER.DAT
C/Windows/System32/config/DEFAULT
2025-09-03T07_52_57_..._ConsoleLog.txt / CopyLog.csv
```

A conta comprometida é a do **steve**, então o foco ficou nos hives dele: `UsrClass.dat` e `NTUSER.DAT`.

> **Sobre os horários:** todos os timestamps deste writeup estão em **UTC**, que é o formato aceito pelo HTB. O próprio `ConsoleLog` do KAPE grava no horário local da máquina (`00:53`), enquanto o nome da pasta da coleta está em UTC (`07:52:57`) — ou seja, a máquina estava em UTC-7. Vale prestar atenção nisso para não misturar fusos na linha do tempo.

### Preparação dos hives
Os hives foram copiados "sujos" (com alterações ainda nos transaction logs). Antes de parsear, aplicamos os `.LOG1/.LOG2` para não perder entradas recentes:

```bash
python3 -m venv venv && . venv/bin/activate
pip install regipy libfwsi-python libfwps-python   # libfwsi/libfwps são dependências do parser de shellbags

regipy-process-transaction-logs UsrClass.dat -p UsrClass.dat.LOG2 -o UsrClass_clean.dat
regipy-process-transaction-logs NTUSER.DAT -p ntuser.dat.LOG1 -s ntuser.dat.LOG2 -o NTUSER_clean.dat
```

## 📚 2. Conceito: o que são Shellbags

**Shellbags** são chaves de registro que o Windows Explorer usa para lembrar as preferências de visualização (tamanho da janela, modo de exibição, ordenação) de cada pasta que o usuário **abriu**. Como efeito colateral, elas viram um histórico de navegação de pastas por usuário, que persiste mesmo depois que a pasta é apagada — inclusive pastas em compartilhamentos de rede, mídias removíveis e o conteúdo de arquivos `.zip` abertos pelo Explorer.

Onde ficam:

| Hive | Chave | O que guarda |
|---|---|---|
| `UsrClass.dat` | `Local Settings\Software\Microsoft\Windows\Shell\BagMRU` e `...\Shell\Bags` | Pastas locais, zips, rede (Windows 7+) |
| `NTUSER.DAT` | `Software\Microsoft\Windows\Shell\BagMRU` e `...\Shell\Bags` | Principalmente pastas de rede/remotas |

Como interpretar:

* `BagMRU` é uma árvore: cada subchave numerada representa uma pasta, e cada valor numérico (`0`, `1`, `2`...) é um **shell item** (binário) com o nome do filho. Juntando a árvore, montamos o caminho completo.
* O valor `MRUListEx` diz a ordem de uso: a **primeira posição** é o filho acessado mais recentemente.
* O **LastWrite da chave** indica quando ela foi alterada pela última vez. Por isso, o filho na primeira posição do `MRUListEx` herda esse horário como **"Last Interacted"** — é o horário que o **ShellBags Explorer / SBECmd** (Eric Zimmerman) mostra, e é o que o HTB usa nas respostas.
* Os shell items de diretório também carregam os timestamps **do sistema de arquivos** (criação/modificação/acesso, em formato DOS com resolução de 2s) do momento em que a entrada foi gravada. São úteis como contexto, mas não são o "acesso" pelo Explorer.

No Windows, a ferramenta padrão é o **ShellBags Explorer** (GUI) ou o **SBECmd** (linha de comando):

```powershell
SBECmd.exe -d C:\caso\C\Users\steve --csv C:\caso\saida
```

Na prática, resolvemos boa parte das perguntas com **busca por string** (Ctrl+F no Registry Explorer / `grep` nos hives): como os nomes de pastas e arquivos ficam gravados em UTF-16LE dentro dos shell items, um `strings -el` já revela quase tudo. Os **horários**, porém, não aparecem como texto — eles vêm do LastWrite das chaves, então para eles é obrigatório usar um parser. No Linux, usamos o plugin de shellbags do **regipy**:

```bash
# busca rápida por strings (o que fizemos primeiro)
strings -el UsrClass.dat | sort -u | less
strings -el NTUSER.DAT | grep -i -E "zip|prodshare|construction"

# parse completo das shellbags (script de apoio com os plugins do regipy)
python3 shellbags_dump.py UsrClass_clean.dat usrclass
python3 shellbags_dump.py NTUSER_clean.dat ntuser
```

<details>
<summary>shellbags_dump.py</summary>

```python
import sys
from regipy.registry import RegistryHive
from regipy.plugins.usrclass.shellbags_usrclass import ShellBagUsrclassPlugin
from regipy.plugins.ntuser.shellbags_ntuser import ShellBagNtuserPlugin

h = RegistryHive(sys.argv[1])
P = ShellBagUsrclassPlugin if sys.argv[2] == 'usrclass' else ShellBagNtuserPlugin
p = P(h, as_json=True); p.run()
for e in p.entries:
    print(f"{e['reg_path'].split('Shell')[-1]} | {e['path']} | LW={e['last_write']} | "
          f"MRU={e['mru_order']} pos={e['mru_order_location']} | "
          f"C={e['creation_time']} M={e['modification_time']} A={e['access_time']}")
```

## 🕵️ 3. Investigação

### Task 1 — Qual arquivo compactado foi baixado pela conta comprometida?
* **Onde:** `UsrClass.dat` ➔ `Local Settings\Software\Microsoft\Windows\Shell\BagMRU\1\0` ➔ `My Computer\Downloads\1.zip`. O shell item mostra criação do arquivo em `07:25:48`, logo depois do primeiro uso do Edge (`07:25:08`, UserAssist no `NTUSER.DAT`). O mesmo nome aparece em `NTUSER.DAT\Software\Microsoft\Windows\CurrentVersion\Explorer\RecentDocs\.zip` (`1.lnk`).
* Encontrado também por string:

```bash
strings -el UsrClass.dat | grep -i "\.zip"
```

* **Resposta:** **`1.zip`**

### Task 2 — Qual utilitário foi trazido para buscar dados sensíveis?
* **Onde:** `UsrClass.dat` ➔ `BagMRU\2\0\0\0\0\0` ➔ `AppData\Local\Temp\Temp1_1.zip\1\Everything-1.4.1.1028.x64.zip`. A pasta `Temp1_1.zip` é o que o Explorer cria ao abrir um zip direto, ou seja, o `1.zip` trazia o pacote `Everything-1.4.1.1028.x64.zip` do **Everything** (busca instantânea de arquivos por nome).
* **Confirmação de execução:** no `NTUSER.DAT`, o **UserAssist** registra `C:\Users\steve\AppData\Local\Temp\Temp1_Everything-1.4.1.1028.x64.zip\everything.exe` executado em `07:26:57`, e a mesma entrada aparece em `Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Compatibility Assistant\Store`.

```bash
strings -el UsrClass.dat | grep -i everything
```

* **Resposta:** **`Everything 1.4.1.1028`**

### Task 3 — Quando a pasta de VPN foi acessada?
* **Onde:** `UsrClass.dat` ➔ `BagMRU\1\1` (filhos de `Documents`). Essa chave tem três entradas: `OnePassword MasterPass`, `Engineers Tab` e `OT Station 3 internal VPN`, com `MRUListEx = 2-1-0`. A entrada `2` (VPN) é a **primeira** da lista, ou seja, a última pasta interagida — e por isso recebe o **LastWrite da chave**, `2025-09-03 07:31:05.130` (o "Last Interacted" do SBECmd).
* O nome da pasta sai no grep, mas o horário só com o parser.
* **Resposta:** **`2025-09-03 07:31:05`**

### Task 4 — Qual diretório contém as senhas da vítima?
* **Onde:** `UsrClass.dat` ➔ `BagMRU\1\1`, valor `0` ➔ `My Computer\Documents\OnePassword MasterPass`.

```bash
strings -el UsrClass.dat | grep -i -E "pass|vpn"
```

* **Resposta:** **`OnePassword MasterPass`**

### Task 5 — Qual o caminho UNC do compartilhamento de rede?
* **Onde:** shell item do tipo *Network Location* em `UsrClass.dat` ➔ `BagMRU\3\0` e em `NTUSER.DAT` ➔ `Software\Microsoft\Windows\Shell\BagMRU\0\0` (`Computers and Devices\Prod-ns-2\\\Prod-ns-2\prodshare`). Além disso, o caminho foi **digitado** na barra do Explorer: `NTUSER.DAT\Software\Microsoft\Windows\CurrentVersion\Explorer\TypedPaths` ➔ `url1 = \\Prod-ns-2\prodshare`.

```bash
strings -el NTUSER.DAT | grep -i prodshare
```

* **Resposta:** **`\\Prod-ns-2\prodshare`**

### Task 6 — Quando está planejada a construção da barragem?
* **Onde:** dentro do compartilhamento existe a pasta `Construction 2027` (`UsrClass.dat` ➔ `BagMRU\3\0\0` e `NTUSER.DAT` ➔ `BagMRU\0\0\0`), que é onde está o arquivo de planos da barragem.
* **Resposta:** **`2027`**

### Task 7 — Qual arquivo compactado estava no compartilhamento?
* **Onde:** `NTUSER.DAT` ➔ `Software\Microsoft\Windows\Shell\BagMRU\0\0\0\0` ➔ `\\Prod-ns-2\prodshare\Construction 2027\Dam Construction Engineer Plans.zip` (nome curto `DAMCON~1.ZIP` no shell item). O arquivo também aparece no `RecentDocs\.zip` (`Dam Construction Engineer Plans.lnk`).

```bash
strings -el NTUSER.DAT | grep -i "dam construction"
```

* **Resposta:** **`Dam Construction Engineer Plans.zip`**

### Task 8 — Quando esse arquivo foi acessado?
* **Onde:** LastWrite da chave `NTUSER.DAT` ➔ `BagMRU\0\0\0\0`, cuja única entrada (`MRUListEx = 0`) é o `Dam Construction Engineer Plans.zip`: `2025-09-03 07:34:04.048`. O `UsrClass.dat` confirma com a chave da mesma pasta (`BagMRU\3\0\0\0`) alterada em `07:34:04.095`.
* **Resposta:** **`2025-09-03 07:34:04`**

### Task 9 — Qual o caminho completo da pasta de staging?
* **Onde:** `UsrClass.dat` ➔ `BagMRU\1\2` (filhos de `Pictures`) ➔ pasta `a`, criada em `07:33:16`, logo antes de surgir o `a.zip` na mesma pasta (`07:34:24`). Montando a árvore (`My Computer\Pictures\a` no perfil do steve), o caminho é `C:\Users\steve\Pictures\a`.
* Aqui o grep não ajuda muito (um nome de uma letra só se perde no meio do hive) — essa saiu da árvore do parser.
* **Resposta:** **`C:\users\Steve\Pictures\a`**

### Task 10 — Quando o arquivo de exfiltração foi acessado?
* **Onde:** `UsrClass.dat` ➔ `BagMRU\1\2` tem `MRUListEx = 1-0`, ou seja, a entrada `1` (`a.zip`) é a mais recente e herda o LastWrite da chave: `2025-09-03 07:34:30.081`.
* **Bônus:** em `BagMRU\2\0\0\0\1\0` aparece `Temp1_a.zip\a\Dam Construction Engineer Plans.zip` (`07:34:40`) — o steve abriu o próprio `a.zip` e o conteúdo era justamente o arquivo copiado do compartilhamento, o que fecha a cadeia de staging. O `RecentDocs\.zip` também lista o `a.zip`.
* **Resposta:** **`2025-09-03 07:34:30`**

## 🛡️ 5. Aprendizados

* **Shellbags provam navegação, não só existência.** Mesmo sem o arquivo, sem Prefetch e sem logs de rede, o registro do usuário mostrou cada pasta aberta, a ordem de uso e quando. Em uma resposta a incidente, coletar `UsrClass.dat` + `NTUSER.DAT` **com os transaction logs** é barato e rende muito — sem aplicar os `.LOG1/.LOG2`, parte das entradas recentes poderia ficar de fora.
* **Saiba qual timestamp está respondendo.** O "acesso" vem do LastWrite da chave aplicado à primeira posição do `MRUListEx`; as datas embutidas no shell item são do sistema de arquivos. Confundir os dois gera horários errados no relatório. E confira sempre o fuso (o log do KAPE estava em horário local).
* **Grep é ótimo para triagem, parser é obrigatório para tempo.** `strings -el` respondeu rápido os nomes (zip, ferramenta, pastas, UNC), mas os horários e a montagem dos caminhos exigem SBECmd/ShellBags Explorer ou o regipy.
* **Detecção para o SOC:**
  * Execução de binários a partir de `%TEMP%\Temp1_*.zip\` (padrão de "abrir exe direto do zip") — regra simples em Sysmon (Event ID 1) / EDR.
  * Ferramentas de busca de arquivos como **Everything** em estações de engenharia/OT não são comuns: vale lista de bloqueio (AppLocker/WDAC) ou alerta por hash/nome.
  * Acesso a compartilhamentos sensíveis (`\\Prod-ns-2\prodshare`) por contas que normalmente não usam aquele share — auditoria de File Share (Event ID 5140/5145) ajuda a correlacionar.
  * Criação de `.zip` em pastas de usuário logo após leitura em share sensível é um padrão clássico de staging; DLP e monitoramento de criação de arquivos compactados ajudam a pegar antes da saída.
* **Higiene:** senhas guardadas em pasta (`OnePassword MasterPass`) e material de VPN de OT em `Documents` facilitam a vida do atacante. Cofre de senhas de verdade e segregação dos acessos de OT reduzem muito o impacto de uma conta comprometida.
