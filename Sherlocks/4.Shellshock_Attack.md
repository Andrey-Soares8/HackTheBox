# 🛡️ HTB Sherlock — Shellshock Attack

**Dificuldade:** Very Easy · **Categoria:** DFIR / Network Forensics · **Artefato:** PCAP (31 pacotes) · **Ferramenta:** Wireshark

---

## 📖 Sinopse

Um PCAP pequeno registra uma tentativa de exploração do **Shellshock (CVE-2014-6271)**. Essa falha no Bash permite executar comandos quando uma variável de ambiente começa com uma definição de função `() { :;};`. Em servidores web com **CGI**, os cabeçalhos HTTP (como `User-Agent`) viram variáveis de ambiente do script. Se o script roda via Bash vulnerável, o que vem depois da função é executado no servidor.

O objetivo é identificar o SO do servidor, o servidor web e a versão, e o comando que o atacante tentou rodar.

---

## 🔍 Reconhecimento do PCAP

1. Abrir `Shellshock_Attack.pcap` no Wireshark.
2. Aplicar o filtro `http` para ver só o tráfego web. Com 31 pacotes, as requisições aparecem rápido.
3. Uma requisição chama a atenção: `GET /exploitable.cgi`. Um alvo `.cgi` é exatamente onde o Shellshock funciona.

---

## 🧩 Análise: Follow HTTP Stream

Botão direito no pacote → **Follow → HTTP Stream** (`tcp.stream eq 2`):

```
GET /exploitable.cgi HTTP/1.1
User-Agent: () { :;}; /bin/ping -c1 10.246.50.2
Host: 10.246.50.6

HTTP/1.1 500 Internal Server Error
Server: Apache/2.2.22 (Ubuntu)
```

**Lendo a requisição:**
- `() { :;};` é a assinatura do Shellshock: uma função vazia que "engana" o Bash.
- `/bin/ping -c1 10.246.50.2` é o comando injetado, que manda **um** ping para o IP do atacante.
- O ping é um teste clássico de execução cega: se o atacante recebe o ICMP, sabe que o servidor executa os comandos dele.

**Lendo a resposta:**
- O cabeçalho `Server: Apache/2.2.22 (Ubuntu)` entrega o servidor, a versão e o SO.
- O `500 Internal Server Error` **não** prova que o ataque falhou. O comando pode rodar antes do CGI quebrar. Para confirmar, procure ICMP de `10.246.50.6` para `10.246.50.2` (filtro `icmp`).

---

## 🏁 Respostas

| Task | Pergunta | Resposta |
|---|---|---|
| 1 | Sistema operacional do servidor | Ubuntu |
| 2 | Servidor de aplicação e versão | Apache/2.2.22 |
| 3 | Comando que o atacante quer executar | /bin/ping -c1 10.246.50.2 |

---

## 🧠 Lições para SOC

- Buscar `() {` em cabeçalhos HTTP (User-Agent, Referer, Cookie) nos logs de acesso e WAF é uma detecção simples de Shellshock.
- Um `User-Agent` com comandos de sistema nunca é legítimo.
- O banner `Server:` vaza a versão. Ocultá-lo (`ServerTokens Prod`) reduz o reconhecimento.
- Uma resposta 500 não descarta o comprometimento: correlacione com tráfego de saída do servidor.

---

**Cadeia:** atacante `10.246.50.2` ➔ `GET /exploitable.cgi` com `User-Agent: () { :;};` ➔ Bash vulnerável no Apache/2.2.22 (Ubuntu) ➔ execução de `/bin/ping -c1 10.246.50.2` (teste de RCE)
